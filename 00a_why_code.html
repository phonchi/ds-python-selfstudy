PROLOGUE · 一個誠實的問題

「AI 三秒就寫得出 BST，那我在這裡幹嘛？」

這是一個好問題，值得認真回答，而不是用「基本功很重要」四個字打發掉。

先承認事實：現在把「幫我用 Python 實作一棵二元搜尋樹，含插入、搜尋、刪除」貼給任何一個主流模型，你會在幾秒內拿到一份看起來很專業、而且大部分情況真的會動的程式碼。這門課教的每一個資料結構，AI 都寫得出來。

所以真正的問題只有一個：換你來當那個要為結果負責的人時，你憑什麼判斷它寫得對不對。

💡 這一頁想說服你的一件事

AI 讓「產出程式碼」變得幾乎免費，於是價值整個移到了另一端：選擇、驗證與取捨。而這三件事，剛好就是資料結構與演算法這門課在教的東西。

PART 01 · 能跑 ≠ 跑得動

AI 給你的是「能跑」，不是「n 變成一百萬還能跑」

你要 AI 排序，它給你一段程式。它能跑。你用 20 筆資料測試，0.001 秒，完美。三個月後資料變成一百萬筆，同一段程式跑了四十分鐘還沒結束。

AI 沒有寫錯。你沒說要多快，它也不知道你的 n 會長多大。而「n 長大時會怎樣」正是這門課第 02 章要教的東西：漸近複雜度。

重點 WHY

n 小的時候，所有演算法看起來都一樣快。這正是「用小資料測試」會騙人的原因。

這張表比較的是成長模型，不是某台電腦的實測秒數。n = 100 萬時，$n^2$ 約是 $n \log_2 n$ 的五萬倍；真正時間仍要用課程第 02 章的 timeit 實驗量測。

AI 不會主動告訴你「你選的這個做法在 n 很大時會爆炸」，除非你問。而你要先知道有這回事，才問得出來。

PART 02 · 選錯結構的代價

AI 會一本正經地選錯資料結構

下面三個都是真實常見的狀況：程式完全正確、測試全過、AI 也覺得沒問題，但效能是災難。這三個坑，剛好對應本站的三章。

看起來很自然的寫法問題正確做法本站對應
queue = []
queue.append(x) / queue.pop(0)		 pop(0) 要把後面所有元素往前搬，是 $O(n)$。處理 n 筆就是 $O(n^2)$。 collections.deque 或自己實作的鏈結佇列，兩端都是 $O(1)$。 第 05 章
if x in my_list: 串列的成員檢查是逐一比對，$O(n)$。放進迴圈就變 $O(n^2)$。 改用 set 或 dict，平均 $O(1)$。 第 07 章
直接遞迴算費氏數列 同一個子問題被重算無數次，複雜度是指數的 $O(2^n)$。 加上記憶化或改成動態規劃，降到 $O(n)$。 第 06 章
⚠️ 最危險的不是錯誤，是「安靜的錯誤」

程式崩潰你至少知道要修。但「跑得出正確答案、只是慢一萬倍」不會噴任何錯誤訊息 —— 它只會在你上線之後、資料長大之後、或是在你交出去給別人用之後，才開始傷人。要抓到這種問題，你必須看得懂那段程式在做什麼，而不只是看它有沒有跑完。

還有一件事：AI 是非決定性的。同一個問題問三次，可能拿到三份不同的實作，其中一份用了 set、一份用了 list。你要有能力挑出哪一份可以用 —— 這個能力沒有捷徑，只能靠自己寫過、量過、踩過。

PART 03 · 學習迴圈

為什麼「學習迴圈」不能被跳過

學會一件事的迴圈長這樣：想法 → 動手試 → 觀察結果 → 修正理解。四步缺一不可，而且卡住、debug、恍然大悟的那個瞬間，正是理解真正發生的地方。

直接把題目丟給 AI、拿回答案貼上去跑，等於把整個迴圈砍掉只剩「觀察結果」。程式會動，作業會過，但你腦袋裡什麼都沒長出來。

🍳 一個比喻

照著食譜做菜，你會做出那道菜；但你不會變成廚師。廚師的能力在於：食材換了、火力不同、客人臨時說不吃辣，他還能重新設計一道菜。你想成為哪一種？

這門課裡真正難的從來不是「寫出 quicksort」。難的是「為什麼 quicksort 平均是 $O(n \log n)$、最壞卻是 $O(n^2)$」、「為什麼要選這個 pivot」、「什麼時候該改用 merge sort」。這些都是推理，抄一百遍程式碼也長不出來。

1提出想法先寫下你預期會發生什麼
→
2動手嘗試自己執行、改變輸入或做小實驗
→
3觀察證據對照輸出、錯誤訊息與效能
→
4修正理解說明為何猜錯，再提出新假設
✅ 那 AI 到底能不能用？

能，而且應該用，但用法要對。把 AI 當助教用，不要當代工：先自己寫、卡住了問「我這裡為什麼錯」、拿到解釋之後自己改。Colab 內建的 Gemini 有一個 Learn Mode，設計上就是只給引導不給完整答案，下一章（00B）會教你怎麼打開它。

PART 04 · 這關你什麼事

說真的，這門課跟你的未來有什麼關係？

① 這是所有量化領域的共同語言

不管你之後做的是資料科學、機器學習、生物資訊、金融工程還是純數學計算，你都會遇到「資料太多、跑太慢」的那一天。到那天，你會需要雜湊表、堆積、圖的最短路徑這些詞。「再租一台更大的機器」買不了多少時間。

② 你早晚要讀別人的原始碼

這門課用的 pythonds3、你未來會用的 NumPy、PyTorch、NetworkX，全部都是別人寫的資料結構。當文件講不清楚、當行為跟你預期不同，唯一的辦法就是打開原始碼看。而原始碼裡面就是 class、就是遞迴、就是樹和圖。

③ 「看得懂」正在變稀有

當產出程式碼變得免費，會產出的人就不值錢了。真正變貴的是能審查的人：能看一眼就說「這裡會 $O(n^2)$」「這個遞迴沒有 base case」「這個 dict 的 key 用了 mutable 物件會炸」。技術面試考白板題、研究團隊要人 code review，考的都是這一層。

🎯 講白一點

AI 會放大你的能力，也會放大你的無知。懂的人用它跑得更快；不懂的人用它把錯誤生產得更快。

PART 05 · 行動指南

開始之前：五個具體習慣

  1. 先估 Big-O，再動手寫。拿到題目先問自己：n 會多大？我這個做法是幾次方？光是養成這個反射，你就贏過一半的人。
  2. 先預測輸出，再按執行。有互動元件時，先在心裡（或紙上）寫下你認為的答案，再操作。猜錯的那一刻，才是你真正學到東西的一刻。
  3. 問「為什麼」而不是「幫我寫」。把「幫我實作 AVL 樹」換成「我的旋轉寫在這裡，為什麼平衡因子沒有更新？」—— 前者你拿到程式碼，後者你拿到理解。
  4. 定期關掉 AI 自己寫一遍。每一章至少挑一個結構，從空白檔案開始不查資料寫出來。寫不出來就是還沒學會，不管你讀過幾遍。
  5. 交出去之前逐行讀自己的程式。如果有任何一行你說不出「這行在幹嘛、拿掉會怎樣」，那行就不算你的。
