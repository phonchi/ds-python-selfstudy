PART 01 · 繼承

is-a：子類別自動拿到父類別的一切 DRY

「有序串列是一種串列」—— 這種 is-a 關係就用繼承。子類別自動擁有父類別所有的屬性與方法，只需要寫「不一樣的那部分」。

OrderedList 繼承 UnorderedList，只覆寫 add()
class UnorderedList: def __init__(self): self._items = [] def add(self, item): self._items.insert(0, item) # 無序：一律插在最前面 def __str__(self): return " -> ".join(map(str, self._items)) class OrderedList(UnorderedList): # ← 括號裡是父類別 def add(self, item): # ← 覆寫：同名方法，不同做法 i = 0 while i < len(self._items) and self._items[i] < item: i += 1 self._items.insert(i, item) # 有序：插到該在的位置 u, o = UnorderedList(), OrderedList() for v in [31, 17, 93, 26]: u.add(v) o.add(v) print("UnorderedList:", u) print("OrderedList :", o) print("是子類別嗎:", issubclass(OrderedList, UnorderedList)) print("MRO:", [c.__name__ for c in OrderedList.__mro__])
預期輸出
UnorderedList: 26 -> 93 -> 17 -> 31
OrderedList  : 17 -> 26 -> 31 -> 93
是子類別嗎: True
MRO: ['OrderedList', 'UnorderedList', 'object']

兩個類別的 __init__ 與 __str__ 完全共用，只有 add 不同。__mro__（Method Resolution Order）就是屬性查找順序：先找 OrderedList，沒有才往 UnorderedList 找，最後是 object。

super()：擴充而不是取代

如果子類別的 __init__ 需要「父類別做的事 再加上 我自己的事」，用 super() 呼叫父類別的版本：

class BinaryTree: def __init__(self, root_obj): self.key = root_obj self.left_child = None self.right_child = None class AVLTree(BinaryTree): def __init__(self, root_obj): super().__init__(root_obj) # 先讓父類別把三個欄位設好 self.balance_factor = 0 # 再補上 AVL 自己需要的欄位
⚠️ 最常見的錯誤

子類別寫了 __init__ 卻忘記呼叫 super().__init__()，於是父類別的欄位根本沒被建立。之後某個繼承來的方法用到那個欄位，就噴 AttributeError——而且錯誤發生的位置離真正的原因很遠，很難找。

🔗 這在資料結構課哪裡會用到 · 第 01、09 章
第 01 章的邏輯閘電路是完整的繼承階層（LogicGate → BinaryGate → AndGate）；第 09 章的 AVLTree 繼承 BinarySearchTree，只覆寫需要維持平衡的那幾個方法。
PART 02 · 多型

同一段程式碼，餵不同的東西進去都能動

多型（polymorphism）的意思是：呼叫端不用知道拿到的是哪一個子類別，只要它「會做這件事」就好。

def print_all(container): """只要傳進來的東西有 __str__ 跟 add()，這個函數就能用。""" for item in [31, 17, 93]: container.add(item) print(container) print_all(UnorderedList()) # 26 -> 93 -> 17 -> 31 的那種 print_all(OrderedList()) # 排好序的那種 # print_all 完全不需要知道自己拿到的是哪一種
🦆 鴨子型別（Duck Typing）

「走起來像鴨子、叫起來像鴨子，那就當它是鴨子。」Python 不檢查型別，只在真的呼叫的時候看方法在不在。所以多型在 Python 裡甚至不需要繼承 —— 兩個毫無關係的類別，只要都有 add()，就能餵進同一個函數。

🔗 這在資料結構課哪裡會用到 · 第 05、07 章
第 07 章的六種排序全部長成 sort(a_list)，你可以把它們互換而不改呼叫端；第 05 章的 Stack 與 Queue 也能被同一段走訪程式碼吃下去。
PART 03 · 相等與雜湊

__eq__ 與 __hash__：一對不能拆開的搭檔

預設情況下，兩個物件只有在是同一個物件時才相等。要讓「內容一樣就算相等」，得自己寫 __eq__。

只寫 __eq__ 會發生的事
class Point: def __init__(self, x, y): self.x, self.y = x, y def __eq__(self, other): return (self.x, self.y) == (other.x, other.y) {Point(1, 2)} # 想把它放進 set
預期輸出
TypeError: unhashable type: 'Point'

Python 的規則是：一旦你定義了 __eq__，物件就自動變成不可雜湊。因為它無法保證你的相等定義跟預設的雜湊值一致 —— 而 set 與 dict 的 key 都需要雜湊值。

補上 __hash__ 之後
class Point: def __init__(self, x, y): self.x, self.y = x, y def __eq__(self, other): return (self.x, self.y) == (other.x, other.y) def __hash__(self): # 相等的物件必須有相同的雜湊值 return hash((self.x, self.y)) print(len({Point(1, 2), Point(1, 2), Point(3, 4)}))
預期輸出
2

三個 Point 放進 set 只剩兩個，因為兩個 Point(1, 2) 被視為同一個。鐵則：a == b 為真時，hash(a) 必須等於 hash(b)。所以雜湊值要從「決定相等的那些欄位」算出來。

🔗 這在資料結構課哪裡會用到 · 第 07 章
這正是雜湊表能運作的前提。第 07 章會講雜湊函數、碰撞與線性探查——而你自訂的物件想當 dict 的 key，就必須讓 __eq__ 與 __hash__ 說法一致，否則同一個 key 會查不到、或出現兩份。
PART 04 · 排序的關鍵

__lt__：定義了「小於」，整個生態系就能用你的物件

沒有 __lt__ 的下場
class Task: def __init__(self, name, priority): self.name = name self.priority = priority def __repr__(self): return f"Task({self.name!r}, {self.priority})" sorted([Task("備份", 5), Task("修 bug", 1), Task("回信", 3)])
預期輸出
TypeError: '<' not supported between instances of 'Task' and 'Task'

sorted()、min()、heapq、二元堆積、快速排序……全部都只做一件事：兩兩比大小。你沒告訴 Python 怎麼比，它就罷工。

補上 __lt__ 與 __eq__ 之後，同一份物件到處都能用
import functools import heapq @functools.total_ordering # 有了 __eq__ 與 __lt__，其餘比較運算子自動補齊 class Task: def __init__(self, name, priority): self.name = name self.priority = priority def __repr__(self): return f"Task({self.name!r}, {self.priority})" def __eq__(self, other): return self.priority == other.priority def __lt__(self, other): # 定義「什麼叫比較小」 return self.priority < other.priority ts = [Task("備份", 5), Task("修 bug", 1), Task("回信", 3)] print("sorted ->", sorted(ts)) print("min ->", min(ts)) heapq.heapify(ts) # 同一份物件，直接丟進二元堆積 print("heappop ->", heapq.heappop(ts), heapq.heappop(ts)) print("total_ordering 送的 >= :", Task("a", 5) >= Task("b", 1))
預期輸出
sorted  -> [Task('修 bug', 1), Task('回信', 3), Task('備份', 5)]
min     -> Task('修 bug', 1)
heappop -> Task('修 bug', 1) Task('回信', 3)
total_ordering 送的 >= : True

只寫了兩個方法，就換到 sorted、min、heapq 全部能用。@functools.total_ordering 會用你的 __lt__ 與 __eq__ 自動補出 >、<=、>=——這門課的 notebook 有 import functools，就是這個用途。

下面這個逐步器把 sorted() 拆開來看：每一次比較都是一次 __lt__ 呼叫。

›按「開始」看排序過程中每一次 __lt__ 被呼叫的樣子。
已呼叫 __lt__：0 次
虛擬碼 CODE
def insertion_sort(a): for i in range(1, len(a)): cur = a[i] j = i - 1 while j >= 0 and cur < a[j]: a[j + 1] = a[j] j -= 1 a[j + 1] = cur
關鍵那一行 WHY

cur < a[j] 就是 cur.__lt__(a[j])。你沒定義它，這一行就 TypeError；你定義錯了，整個排序就悄悄排錯 —— 而且不會噴任何錯誤。

🔗 這在資料結構課哪裡會用到 · 第 07、09 章
第 07 章六種排序法的核心都是這一次比較；第 09 章的 PriorityQueue（二元堆積）在 percolate up/down 時每一步都在比大小。想把自訂的工作物件丟進優先佇列？先給它 __lt__。
PART 05 · 容器協定

讓自訂結構支援 len()、[]、in、for

Python 的內建語法其實都是 dunder 的門面。實作對應的 dunder，你的類別就能用得跟內建型別一樣。

你寫的語法Python 實際呼叫本站哪一章用到
›點表格任一列，看那個 dunder 的說明與課程對應。
說明 DETAIL
點左邊表格的任一列。
一次實作四個協定
class Bag: def __init__(self, items): self._items = list(items) def __len__(self): # len(b) return len(self._items) def __getitem__(self, i): # b[1] return self._items[i] def __contains__(self, x): # x in b return x in self._items def __iter__(self): # for x in b return iter(self._items) b = Bag(["紅", "綠", "藍"]) print("len(b) ->", len(b)) print("b[1] ->", b[1]) print("'綠' in b ->", "綠" in b) print("for 迴圈 ->", [x for x in b])
預期輸出

b[1]      -> 綠
'綠' in b -> True
for 迴圈  -> ['紅', '綠', '藍']

Bag 從頭到尾沒有繼承任何東西，卻已經能用 len()、下標、in 與 for。這就是鴨子型別的力量：能力來自你實作了哪些協定，不是來自你繼承了誰。

PART 06 · 設計抉擇

組合 vs 繼承：Deque 該繼承 list 嗎？

做一個雙端佇列，最省事的寫法看起來是直接繼承 list。試試看會怎樣：

繼承 list 的陷阱
class BadDeque(list): # 繼承 list：看似省事 def add_front(self, x): self.insert(0, x) d = BadDeque() d.add_front(1) d.add_front(2) print("內容:", d) print("但外面還能呼叫:", [m for m in ("sort", "reverse", "insert") if hasattr(d, m)])
預期輸出
內容: [2, 1]
但外面還能呼叫: ['sort', 'reverse', 'insert']

問題不在它不能動，而在它能做的事太多了：使用者可以對你的 Deque 呼叫 sort()、reverse()、insert(3, x)——這些操作全都違反雙端佇列「只能從兩端進出」的契約，而你完全擋不住。

繼承（is-a）組合（has-a）
寫法class Deque(list):self._items = []
對外露出什麼父類別所有方法，擋不掉只有你自己寫的方法
能換底層實作嗎不能，已經綁死 list能，改內部一行就好
什麼時候該用子類別真的是一種父類別，而且父類別的每個方法對它都合理絕大多數的資料結構
🎯 判斷法則

問自己一句：「父類別的每一個方法，用在子類別身上都說得通嗎？」只要有一個說不通（例如對 Deque 呼叫 sort()），就不要繼承，改用組合。
OrderedList 繼承 UnorderedList 是合理的（父類別的每個方法對它都成立）；Deque 繼承 list 不合理。

🔗 這在資料結構課哪裡會用到 · 第 05 章
pythonds3 的 Stack、Queue、Deque 全部採用組合而非繼承 list——現在你知道為什麼了。
PART 07 · 收尾

@dataclass 與自訂例外

少寫一點樣板：@dataclass

一個裝飾器換掉四個 dunder
from dataclasses import dataclass @dataclass(order=True) # 自動生成 __init__ / __repr__ / __eq__ / __lt__ class Item: priority: int # 比較時按照欄位宣告順序 name: str items = [Item(5, "備份"), Item(1, "修 bug")] print(items[0]) print("自動有 __eq__ :", Item(1, "x") == Item(1, "x")) print("order=True 就有 __lt__:", sorted(items))
預期輸出
Item(priority=5, name='備份')
自動有 __eq__      : True
order=True 就有 __lt__: [Item(priority=1, name='修 bug'), Item(priority=5, name='備份')]

@dataclass 自動生成 __init__、__repr__、__eq__；加上 order=True 連 __lt__ 都有了，比較時按欄位宣告順序。適合單純裝資料的類別；但需要自訂邏輯（例如 Node 的 _next 串接）時，還是自己寫 class。

自訂例外：讓錯誤訊息說人話

class EmptyStackError(Exception): """對空堆疊做 pop 或 peek 時拋出。""" class Stack: def __init__(self): self._items = [] def pop(self): if not self._items: raise EmptyStackError("堆疊是空的，沒有東西可以彈出") return self._items.pop() s = Stack() try: s.pop() except EmptyStackError as e: print("接住了:", e)

自訂例外只要繼承 Exception 就好，通常連內容都不用寫。好處是呼叫端可以精準地只接住這一種錯誤，而不是用一個 except 把所有 bug 一起吞掉。例外的完整語法見 P7。

🔗 這在資料結構課哪裡會用到 · 第 05、09 章
pythonds3 的 Stack 對空的 pop 會拋 IndexError；自己實作時，拋一個講得清楚的自訂例外會讓 debug 快很多。
