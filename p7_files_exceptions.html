PROLOGUE · 開場

程式結束，變數就消失了

你的變數住在記憶體裡，程式一結束就什麼都沒了。要讓資料活過這一次執行，就得寫進檔案；要讓別人的資料進到你的程式，就得從檔案（或網路）讀進來。

而只要牽涉到「外面的世界」——檔案可能不存在、路徑可能打錯、網路可能斷線——程式就有失敗的可能。例外處理就是在說「失敗的時候該怎麼辦」。這兩件事天生綁在一起，所以放同一頁。

PART 01 · 路徑

pathlib：不要再自己串字串了

路徑分隔符在 Windows 是反斜線、在 macOS／Linux 是斜線。自己用字串拼會在換平台時壞掉；pathlib.Path 幫你處理掉這件事。

Path 的基本操作
from pathlib import Path p = Path("data") / "words.txt" # 用 / 串路徑，Windows 與 macOS 都對 print("路徑物件 :", p) print("副檔名 :", p.suffix) print("檔名（不含副檔）:", p.stem) print("父目錄 :", p.parent) print("存在嗎 :", p.exists())
預期輸出
路徑物件        : data/words.txt
副檔名          : .txt
檔名（不含副檔）: words
父目錄          : data
存在嗎          : False

Path('data') / 'words.txt' 用除號串路徑，是 __truediv__ 這個 dunder 的運算子重載（見 P9）。最後一行是 False，因為這個檔案還沒被建立。

寫法意思
Path("a") / "b" / "c.txt"組出 a/b/c.txt，跨平台正確
p.exists()檔案或目錄存在嗎
p.suffix / p.stem / p.name副檔名／不含副檔的檔名／完整檔名
p.parent上一層目錄
Path("data").mkdir(exist_ok=True)建目錄，已存在也不報錯
list(Path(".").glob("*.txt"))列出符合樣式的所有檔案
📍 相對路徑是相對於「執行時的工作目錄」

不是相對於程式檔所在的位置。這是「在我電腦上跑得動，在 Colab 上就找不到檔案」的頭號原因。不確定的時候印一下 Path.cwd() 看看你到底站在哪。

PART 02 · 讀檔

with open(...)：開了一定會關

with 區塊結束時會自動關閉檔案，即使中間拋出例外也一樣。這是唯一該用的寫法。

寫進去再讀回來
from pathlib import Path Path("data").mkdir(exist_ok=True) # 沒有就建，有了也不報錯 p = Path("data") / "words.txt" words = ["FOOL", "POOL", "POLL", "POLE", "PALE", "SALE", "SAGE"] with open(p, "w", encoding="utf-8") as f: # "w" 會清空重寫 for w in words: f.write(w + "\n") # write 不會自動換行 with open(p, encoding="utf-8") as f: # 不寫模式就是唯讀 lines = [line.strip() for line in f] # 逐行迭代，不必一次讀進記憶體 print("讀回幾行:", len(lines)) print("前三行 :", lines[:3])
預期輸出
讀回幾行: 7
前三行  : ['FOOL', 'POOL', 'POLL']

三個重點：① with 保證關檔。② f.write() 不會自動換行，要自己加。③ 直接對檔案物件跑 for 迴圈就是逐行讀取——處理大檔時這比 read() 一次吞進記憶體好太多。

模式行為檔案不存在時
"r"（預設）唯讀FileNotFoundError
"w"寫入，先清空原內容自動建立
"a"附加到結尾自動建立
"x"只在檔案不存在時建立自動建立；已存在則報錯
⚠️ "w" 會直接清空整個檔案

而且不會問你。想接著寫請用 "a"。另外處理文字檔時養成習慣加 encoding="utf-8"，否則在 Windows 上讀中文很容易變亂碼。

🔗 這在資料結構課哪裡會用到 · 第 08 章

PART 03 · 寫檔與 JSON

把結構化資料存下來

純文字適合一行一筆的資料。如果你要存的是巢狀的字典與串列（例如一張相鄰串列、一份實驗結果），用 json 最省事。

import json from pathlib import Path graph = {"FOOL": ["POOL", "FOIL"], "POOL": ["FOOL", "POLL"]} with open("graph.json", "w", encoding="utf-8") as f: json.dump(graph, f, ensure_ascii=False, indent=2) # 寫出去 with open("graph.json", encoding="utf-8") as f: back = json.load(f) # 讀回來 print(back["FOOL"]) # ['POOL', 'FOIL'] print(back == graph) # True
💡 四個名字別搞混

json.dump 寫到檔案、json.dumps 轉成字串（s = string）；json.load 從檔案讀、json.loads 從字串讀。本站的詞彙卡與題庫母檔（data/ 底下那些 .json）就是這樣存的。

PART 04 · 從網路讀

資料不在你電腦上的時候 課程真的會用到

課程 notebook 用 urllib.request 直接把網路上的字典檔抓下來，這樣在 Colab 上也不用先上傳檔案。

import urllib.request URL = "https://raw.githubusercontent.com/.../words.txt" with urllib.request.urlopen(URL) as resp: text = resp.read().decode("utf-8") # 拿到的是 bytes，要自己解碼 words = [w.strip() for w in text.splitlines() if w.strip()] print(len(words), words[:3])
✅ 為什麼不直接 open()

因為在 Colab 上你的本機檔案不存在。從網址讀讓同一份 notebook 在任何環境都跑得動——這是很值得養成的習慣。缺點是需要網路，而且對方的檔案可能哪天就搬家了。

PART 05 · 例外

例外不是「壞掉」，是「這條路走不通，換你決定怎麼辦」

五個你一定會遇到的例外
cases = [ ("開不存在的檔案", lambda: open("no_such_file.txt")), ("串列索引超界", lambda: [1, 2, 3][10]), ("字典查無此鍵", lambda: {"a": 1}["b"]), ("字串轉整數失敗", lambda: int("FOOL")), ("除以零", lambda: 1 / 0), ] for label, fn in cases: try: fn() except Exception as e: print(f"{label:8s} -> {type(e).__name__}: {e}")
預期輸出
開不存在的檔案  -> FileNotFoundError: [Errno 2] No such file or directory: 'no_such_file.txt'
串列索引超界   -> IndexError: list index out of range
字典查無此鍵   -> KeyError: 'b'
字串轉整數失敗  -> ValueError: invalid literal for int() with base 10: 'FOOL'
除以零      -> ZeroDivisionError: division by zero

認得例外的名字比背細節重要：看到 KeyError 就知道是查了不存在的鍵，看到 IndexError 就知道是索引超出範圍。這是 debug 最快的捷徑。

›選一種情況，再按「下一步」。
0 / 5
虛擬碼 CODE
try: f = open(path) except FileNotFoundError: return 0 else: return len(f.readlines()) finally: close_things()
四個區塊的分工 RULE

try：可能失敗的那幾行，只放會失敗的部分。
except：失敗時的處理。
else：沒有失敗才跑，放「成功之後才有意義」的程式。
finally：成功失敗都跑，用來收尾。

完整的執行順序（真的跑過的輸出）
def read_count(path): try: f = open(path, encoding="utf-8") except FileNotFoundError: print(" except ：檔案不存在，回傳 0") return 0 else: print(" else ：開檔成功才會跑到這裡") return len(f.readlines()) finally: print(" finally：不管成功失敗都會跑") print("存在的檔:", read_count("data/words.txt")) print("不存在 :", read_count("data/nope.txt"))
預期輸出
  else   ：開檔成功才會跑到這裡
  finally：不管成功失敗都會跑
存在的檔: 7
  except ：檔案不存在，回傳 0
  finally：不管成功失敗都會跑
不存在  : 0

注意 finally 的位置：連 return 都攔不住它，函式回傳之前一定會先跑完 finally。這就是它用來關檔、釋放資源的原因。

⚠️ 不要寫裸的 except:

except: 或 except Exception: 會把所有錯誤一起吞掉，包括你自己打錯字造成的 NameError。結果就是程式默默給出錯的答案，而你完全不知道。接住你預期會發生的那一種就好。

PART 06 · 主動拋出

raise 與自訂例外

你自己寫的資料結構也該在被誤用時抗議。raise 就是「這個狀況我處理不了，交給呼叫我的人決定」。

Stack 對空的 pop 抗議
class EmptyStackError(Exception): """對空堆疊做 pop 時拋出。""" class Stack: def __init__(self): self._items = [] def pop(self): if not self._items: raise EmptyStackError("堆疊是空的，沒有東西可以彈出") return self._items.pop() s = Stack() try: s.pop() except EmptyStackError as e: print("接住了:", type(e).__name__, "-", e)
預期輸出
接住了: EmptyStackError - 堆疊是空的，沒有東西可以彈出

自訂例外只要繼承 Exception，連內容都不用寫。好處是呼叫端可以精準地只接住這一種，而不是用一個 except 把所有 bug 一起吞掉。這就是 P9 繼承的實際應用。

🎯 什麼時候該 raise

當函式無法完成它承諾的事時。空堆疊沒有東西可以彈出、除數是零、參數型別根本不對——這些都不該悄悄回傳 None 假裝沒事，因為那會讓錯誤在很遠的地方才爆出來，難以追查。

🔗 這在資料結構課哪裡會用到 · 第 05、06 章
第 05 章的堆疊與佇列在空的時候操作會拋例外；第 06 章遞迴沒有正確收斂時會拋 RecursionError——那跟環境無關，是你的基底情況沒寫對。
