PROLOGUE · 開場

一個資料結構，就是一個類別

先看本站首頁那段裝飾用的程式碼 —— 它不是隨便挑的：

class Stack: def __init__(self): self.items = [] def push(self, item): self.items.append(item) def pop(self): return self.items.pop()

這就是這門課的形狀。資料結構 = 資料（要存什麼）＋ 操作（能對它做什麼），而 Python 用來把這兩件事包在一起的工具就是 class。

抽象資料型別（ADT）的說法Python 的說法例子
這個結構「存什麼」屬性（attribute）self._items
這個結構「能做什麼」方法（method）push()、pop()
結構的規格（介面）class 定義class Stack:
實際被建立出來的一個結構物件／實例（object / instance）s = Stack()
💡 這一頁的目標

讀完你要能從空白檔案寫出一個 Node 和一個 Stack，並且說得出 self 是什麼、__init__ 什麼時候被呼叫、為什麼要寫 __str__。這三件事撐起第 03 章之後的每一章。

PART 01 · 類別與實例

藍圖與成品 四個必背詞

類別（class）是藍圖，物件（object）是照著藍圖蓋出來的東西。藍圖只有一份，蓋出來的房子可以有很多間，每一間的門牌、住戶各自不同。

詞是什麼在程式裡長什麼樣
類別 class藍圖／規格class Node:
物件／實例 object / instance照藍圖做出來的一個具體東西n = Node(93)
屬性 attribute物件身上存的資料n._data
方法 method綁在物件上的函數n.get_data()
類別、實例與 self：同一張圖看懂
藍圖：class Node
__init__(self, data)
get_data(self)
方法只存一份
實例 n1 = Node(93)
n1.__dict__ = {'_data': 93, '_next': None}
實例 n2 = Node(17)
n2.__dict__ = {'_data': 17, '_next': None}

n1.get_data() 是語法糖，實際呼叫 Node.get_data(n1)；因此方法裡的 self 就是 n1。建立 n1 時，Python 先配置實例，再呼叫 Node.__init__(n1, 93) 填入自己的狀態。

最小可用的 Node 類別（第 04 章鏈結串列的主角）
class Node: """鏈結串列的節點：存一個值，再指向下一個節點。""" def __init__(self, node_data): self._data = node_data self._next = None def __str__(self): return f"Node({self._data})" n = Node(93) print(n) print(n._data, n._next) print(type(n), isinstance(n, Node))
預期輸出
Node(93)
93 None
<class '__main__.Node'> True

三個觀察：① Node(93) 看起來像呼叫函數，其實是建立一個實例，會自動去跑 __init__。② _next 一開始是 None，代表「後面還沒接東西」。③ type() 告訴你它是哪個類別的實例。

🔗 這在資料結構課哪裡會用到 · 第 04 章
Node 是鏈結串列的基本磚塊。整章都在做同一件事：建立 Node、修改它的 _next、沿著 _next 走訪。看不懂 class，那一章就只能死背。
PART 02 · 建構式

__init__ 與 self：兩個最容易卡住的地方

__init__ 不是「建立物件」，是「把剛建好的物件初始化」

你寫 n = Node(93) 的時候，Python 做兩件事：先配置一個空的物件，然後自動呼叫 n.__init__(93) 把它填好。所以 __init__ 裡面做的事就是「這個物件一出生要帶著哪些資料」。

名字前後各兩條底線的方法叫 dunder method（double underscore），它們是 Python 跟你的類別溝通的暗號：你不會直接呼叫 __init__，是 Python 在對的時機幫你叫。

self 不是關鍵字，它只是第一個參數

方法被呼叫時，Python 會自動把「是誰呼叫的」塞進第一個參數。n.get_data() 實際上等同於 Node.get_data(n)。習慣上這個參數命名為 self，但那只是慣例 —— 重點是它一定要存在。

忘記寫 self 的典型錯誤（值得認得這個訊息）
class Broken: def __init__(self, x): self.x = x def show(): # ← 忘了寫 self return "hi" b = Broken(1) b.show()
預期輸出
TypeError: Broken.show() takes 0 positional arguments but 1 was given

訊息在說：「你這個方法宣告成不吃參數，可是我傳了一個進去」——那個被傳進去的就是 b 自己。看到 takes 0 positional arguments but 1 was given，九成是漏了 self。

PART 03 · 屬性與方法

實例屬性、類別屬性，還有 Python 找屬性的順序

實例屬性寫在 __init__ 裡、掛在 self 上，每個物件各有一份。類別屬性寫在 class 區塊的最外層，整個類別共用一份。

類別屬性的經典陷阱
class Counter: total = 0 # 類別屬性：整個 Counter 家族共用一份 def __init__(self, name): self.name = name # 實例屬性：每個物件各自一份 Counter.total += 1 a, b = Counter("a"), Counter("b") print("a.name =", a.name, " b.name =", b.name) print("Counter.total =", Counter.total, " a.total =", a.total) a.total = 99 # 這行沒有改到類別屬性，而是「新建」了一個實例屬性 print("a.total =", a.total, " Counter.total =", Counter.total, " b.total =", b.total)
預期輸出
a.name = a  b.name = b
Counter.total = 2  a.total = 2
a.total = 99  Counter.total = 2  b.total = 2

看最後一行：a.total = 99 沒有改到 Counter.total，它在 a 身上新建了一個同名的實例屬性，從此把類別屬性遮住了。要改共用的那一份，必須寫 Counter.total = 99。

為什麼會這樣？因為 Python 找屬性有固定順序：先找實例自己，找不到才往類別找，再往父類別找。下面這個逐步器把這個過程演一次。

›選一個屬性，再按「下一步」。
0 / 2
屬性查找（簡化版）

① 實例自己的 __dict__
② 找不到才沿類別的 MRO：目前類別 → 父類別 → object
③ 都沒有 → AttributeError

為什麼要懂 WHY

這個順序解釋了兩件事：類別屬性為什麼會被實例屬性「遮住」，以及 P9 的方法覆寫為什麼有效 —— 子類別的方法先被找到，父類別的就不會被用到。

🔗 這在資料結構課哪裡會用到 · 第 03、05 章
ArrayList 用類別屬性存「預設容量」、用實例屬性存「目前有幾個元素」；Stack 的 _items 則一定要是實例屬性 —— 否則所有 Stack 會共用同一個 list，那就爆了。
PART 04 · 封裝

底線慣例與 @property

封裝的意思是：把內部怎麼存的細節藏起來，只暴露有意義的操作。使用 Stack 的人只該知道 push / pop，不該去戳 s._items；這樣你之後想把 list 換成鏈結串列，外面的程式碼完全不用改。

寫法意思Python 真的會擋嗎
self.data公開，外面可以自由使用—
self._data慣例上的內部屬性，「請不要從外面碰」不會。純粹是給人看的約定
self.__data觸發名稱改寫（name mangling），實際變成 _ClassName__data只是變得比較難碰，仍然碰得到

Python 沒有 private 關鍵字，靠的是「大家都是成年人」的約定。pythonds3 的原始碼大量使用單底線加上 @property：

class Node: def __init__(self, node_data): self._data = node_data self._next = None @property def data(self): # 讀取：n.data（注意沒有括號） return self._data @data.setter def data(self, new_data): # 寫入：n.data = 5 self._data = new_data n = Node(93) print(n.data) # 93 ← 讀起來像屬性，其實跑了一個方法 n.data = 26 # ← 寫起來像屬性，其實跑了 setter print(n.data) # 26
✅ @property 的好處

外面用起來像單純的屬性（n.data），但你隨時可以在 getter/setter 裡加檢查、加轉換、加記錄，而不用改任何呼叫端的程式碼。這就是封裝的實際價值。

🔗 這在資料結構課哪裡會用到 · 第 04、09 章
pythonds3 的 Node 與 BinaryTree 都用 @property 包住 data、next、left_child。看原始碼時看到 @property 不要慌，它就是個加了檢查的屬性。
PART 05 · 印得出來

__str__ 與 __repr__：讓你的物件說人話

沒有 __str__ 的下場
class Plain: def __init__(self, v): self.v = v p = Plain(7) print(p)
預期輸出
<__main__.Plain object at 0x7f3c9c1d4e50>

這串東西只告訴你「它是個 Plain 物件、放在這個記憶體位址」——對 debug 完全沒有幫助。想像你 print 一棵有 20 個節點的樹，看到 20 行這種東西。

方法誰會呼叫它該寫成什麼樣
__str__str(x)、print(x)、f-string給人看的：好讀、簡潔
__repr__互動式直譯器直接打變數名、repr(x)、印一個裝著物件的 list 時給開發者看的：精確、最好能貼回程式碼重建物件
💡 只想寫一個的話，寫 __repr__

因為當 __str__ 沒定義時，print() 會退而使用 __repr__；反過來不成立。而且 print(list_of_nodes) 印出的是每個元素的 __repr__，不是 __str__ —— 這是很多人第一次覺得「我明明寫了 __str__ 為什麼還是亂碼」的原因。

🔗 這在資料結構課哪裡會用到 · 第 04、09 章
沒有 __str__，你在 debug 鏈結串列與二元樹時等於瞎子摸象。第 09 章的 BinaryTree.__str__ 甚至是遞迴寫的：印自己、再印左右子樹。
PART 06 · 組合

用現成的東西蓋新的東西 has-a

要做一個 Stack，你不需要從零管理記憶體 —— 直接持有一個 list 就好。這種「A 擁有一個 B」的關係叫做組合（composition），是資料結構課裡最常見的蓋法。

完整的 Stack：這一份會在第 05 章反覆出現
class Stack: """堆疊 ADT：後進先出。內部用一個 list 存元素（這叫「組合」）。""" def __init__(self): self._items = [] # has-a：Stack 擁有一個 list def push(self, item): self._items.append(item) # list 尾端是堆疊頂端，append/pop 都是 O(1) def pop(self): return self._items.pop() def peek(self): return self._items[-1] def is_empty(self): return not self._items def size(self): return len(self._items) def __len__(self): # 讓內建的 len() 也能用 return len(self._items) def __str__(self): # 讓 print() 印得出人看得懂的東西 return "底 " + " | ".join(map(str, self._items)) + " 頂" s = Stack() for c in "abc": s.push(c) print(s) print("len(s) =", len(s), " s.size() =", s.size()) print("pop ->", s.pop(), " 剩下:", s)
預期輸出
底 a | b | c 頂
len(s) = 3  s.size() = 3
pop -> c  剩下: 底 a | b 頂

重點在 self._items = [] 這一行：Stack 不是一個 list，Stack 有一個 list。外面的人只看得到 push/pop/peek，看不到裡面是 list ——所以你哪天要把它換成鏈結串列，外面一行都不用改。

隨堂 2 · 選對那一端

上面的 Stack 把 list 的尾端當成堆疊頂端。如果改成把 list 的開頭當頂端（insert(0, x) 與 pop(0)），會發生什麼事？

(A) 完全一樣，只是寫法不同
(B) 行為一樣正確，但 push／pop 從 $O(1)$ 變成 $O(n)$
(C) 會出錯，list 不支援從開頭刪除
🔗 這在資料結構課哪裡會用到 · 第 05 章
Stack、Queue、Deque 三個 ADT 在 pythonds3 裡全部用同一招：持有一個 list，只是選擇從哪一端操作。選錯端就是 O(n)。
PART 07 · 動手做

從空白檔案寫一個 Node 與最小串列

讀到這裡，把網頁關掉，開一個空的 notebook，試著不看答案寫出來：

練習規格 TRY IT

① 寫一個 Node 類別，建構式吃一個值，存成 _data，並把 _next 設成 None。
② 幫它加上 __repr__，讓 print 一個 Node 的 list 看得懂。
③ 寫一個 MiniList，內部只存一個 _head；提供 add(item)（加在最前面）與 __str__（沿著 _next 走一遍，用箭頭串起來）。
④ 加入 31、17、93、26 之後，print 出來應該是 26 -> 93 -> 17 -> 31。

class Node: def __init__(self, node_data): self._data = node_data self._next = None def __repr__(self): return f"Node({self._data})" class MiniList: def __init__(self): self._head = None def add(self, item): new = Node(item) new._next = self._head # 新節點指向原本的第一個 self._head = new # 頭換成新節點 def __str__(self): out, cur = [], self._head while cur is not None: out.append(str(cur._data)) cur = cur._next return " -> ".join(out) lst = MiniList() for v in [31, 17, 93, 26]: lst.add(v) print(lst) # 26 -> 93 -> 17 -> 31
🎯 過關標準

如果你能不看上面這段、憑理解把 add 那兩行的順序寫對（先接上舊的頭，再把頭換成新的），你已經準備好進第 04 章了。順序寫反會怎樣？把它跑一次就知道 —— 那個錯誤本身就是最好的教材。
