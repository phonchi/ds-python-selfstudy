PART 01 · 函數簡介

為什麼需要函數？抽象化與分治法

開發與維護大型程式最好的方法，是把它拆解成較小的部分——這個技巧叫分治法（divide and conquer）。而在程式設計中，抽象化（abstraction）指的是把演算法中子步驟的複雜性隱藏在一個函數（function）裡的做法。

寫函數，其實就是幫某一段程式碼的邏輯取一個名字：之後我們只要看函數名稱就知道它的用途，不必每次都重新讀懂實作細節。我們早就用過內建函數了，例如 print()、str()、len()——括號內放的值稱為引數（argument）。當函數出現在運算式或敘述中，就稱為一次函數呼叫（function call）。

換個生活中的例子：想像你走進一間手搖飲店，店員照著牆上貼的配方單做飲料——五分糖、去冰、加珍珠——不用每接一張單就重新發明一次泡茶的方法。這張配方單就是函數：用 def 把泡茶的步驟寫一次，之後想喝的時候，只要「點單」呼叫它就好，不必再把每個步驟想一遍。

👨‍⚕️ 用函數的兩大好處

① 可以在程式的各個位置重複呼叫同一段程式碼，不必複製貼上。
② 讓程式更容易修改：只要改函數內部的程式碼，所有呼叫它的地方都會自動套用新版本。

簡單說：函數就像一個黑盒子——有輸入（參數）、有輸出（回傳值），使用者不需要知道盒子裡面怎麼運作。

先劇透一下：這一章結束前，你會親手玩到（而且看懂程式碼的每一行）兩個小遊戲——「猜數字」和「龍與洞穴」。它們都是用今天要學的 def、引數、return 和模組寫成的，把函數學完，你就能自己看懂它們是怎麼運作的。

PART 02 · 函數的定義與呼叫

def 敘述：定義並呼叫你自己的函數

用 def 敘述定義函數，緊接在 def 函數名稱(): 後方、有縮排的程式碼就是函數主體。呼叫函數時傳入的值稱為引數，函數定義中負責接住這些值的變數則稱為參數（parameter）。

def hello(name): print('Hello,', name) hello('Alice') hello('Bob')

第一次呼叫 hello('Alice') 時，Python 會把參數 name 自動設定為 'Alice'，執行函數主體、印出 Hello, Alice；接著才換 hello('Bob')。

⚠ 函數執行結束後，參數就被遺忘了

如果在 hello('Bob') 之後加一行 print(name)，會產生 NameError！因為 name 只存在於呼叫 hello() 時建立的區域範圍中，函式一回傳，這個區域範圍就被銷毀，name 也跟著消失。（這正是下面 P05「區域 vs 全域範圍」要探討的主題。）

位置引數：依照順序配對

最簡單的引數配對方式，是依照呼叫時的順序對應到參數，這種方式稱為位置引數（positional argument）：

def describe_pet(animal_type, pet_name): """ 顯示寵物的資訊。 你可以在這裡撰寫多行說明！ """ print("\n我有一隻", animal_type + "。") print("我那隻", animal_type + " 的名字是", pet_name.title() + "。") describe_pet('Pokemon', 'Harry')

呼叫時 'Pokemon' 依序對應到 animal_type、'Harry' 對應到 pet_name。函數主體第二行的三引號字串是文件字串（docstring），用來描述函數的功能——如果你用 help(describe_pet) 查詢，這段說明也會一併顯示出來。

⚠ 初學者常犯的兩個小錯

① 呼叫函數時忘記加括號 ()——當函數不需要參數時特別容易忘記。
② 忽略縮排，沒有把函數主體的程式碼與外面呼叫函數的程式碼區分清楚。

🎬 互動：拆開一次函數呼叫——呼叫堆疊動畫

每次呼叫函數，Python 都會在呼叫堆疊（call stack）最上方建立一個新的「函數 frame」，存放這次呼叫的參數與區域變數；函數執行到 return 時，這個 frame 就會被丟棄，回傳值連同控制權一起送回呼叫處。用下面這個有回傳值的小函數逐步看看：

呼叫堆疊是什麼？

全域範圍只有一個，程式一開始就建立；每呼叫一次函數，就在堆疊上疊一個新的區域 frame。frame 之間互不干擾，函式回傳時最上面的 frame 會被銷毀。

help() 與關鍵字引數小預告

使用 help(print) 可以看到 print() 其實還有其他參數，例如 sep：預設分隔符號是空白，但可以改變它。

print("8", "9", sep="*") # 輸出：8*9

像 sep="*" 這樣「用名稱指定引數」的寫法，就是下一節要介紹的關鍵字引數。

PART 03 · 引數的進階用法

關鍵字引數與預設參數值

關鍵字引數（keyword argument）是以「名稱－值」配對的方式傳入引數，不需要擔心呼叫時的順序，也讓每個引數的用途更清楚：

describe_pet(animal_type='Pokemon', pet_name='Harry')

函數本身沒有改變，但 Python 讀到這行時，會直接依名稱把 'Pokemon' 指派給 animal_type、'Harry' 指派給 pet_name——順序完全不影響結果。

預設參數值

撰寫函式時可以定義預設參數值：呼叫時有提供對應引數就用引數的值，沒提供就用預設值。

def describe_pet(pet_name, animal_type='dog'): """ 顯示寵物的相關資訊。 這裡為 animal_type 參數設定了預設值。 """ print("\n我有一隻 " + animal_type + "。") print("我那隻 " + animal_type + " 的名字叫做 " + pet_name.title() + "。") describe_pet('willie') # 沒給 animal_type → 使用預設值 'dog'

注意函式定義中參數順序做了調整：沒有預設值的 pet_name 放在前面，有預設值的 animal_type 放在後面。這不是巧合——Python 規定有預設值的參數必須排在沒有預設值的參數之後，否則會發生語法錯誤，因為 Python 需要先確定哪些是「必填」的位置引數。

⚠ 參數順序寫反了會怎樣？

def describe_pet(animal_type='dog', pet_name): 這樣的定義會直接產生 SyntaxError: parameter without a default follows parameter with a default——因為沒有預設值的 pet_name 排在有預設值的 animal_type 後面，Python 無法判斷位置引數該怎麼配對。

PART 04 · 回傳值與 None

return 敘述：函數呼叫也是一個值

呼叫 len('Hello') 會得到一個整數——這個函數呼叫所計算出的值，稱為傳回值（return value）。自訂函數時，用 return 敘述來指定要回傳什麼：

import random def getAnswer(answerNumber): if answerNumber == 1: return '結果是肯定的' elif answerNumber == 2: return '毫無疑問' elif answerNumber == 3: return '是的' elif answerNumber == 4: return '回覆不明，再試一次' elif answerNumber == 5: return '請稍後再問' elif answerNumber == 6: return '請更加專心並再問一次' r = random.randint(1, 6) fortune = getAnswer(r) print(fortune)

程式執行到 getAnswer(r) 時，會跳到函數開頭，把 r 的值存入參數 answerNumber，依條件回傳其中一個字串；呼叫結束後，程式回到原本呼叫的那一行，把回傳的字串指派給 fortune。像這種會回傳值的函數有時被稱為 fruitful function（有回傳值的函數）。

None：代表「沒有值」的值

Python 中有一個特殊值 None，代表「沒有值」，它是 NoneType 型別中唯一的值。None 最常見的用途，就是作為沒有 return 敘述的函數的傳回值：

spam = print('Hello!') print(spam) type(spam) # 輸出：Hello! # 接著：None # 接著：<class 'NoneType'>

print() 負責在螢幕上顯示文字，本身不需要回傳任何資料——但因為所有函數呼叫都必須有傳回值，所以 print() 就回傳 None。像這樣沒有回傳值的函數稱為 void function（無回傳值的函數）。Python 會自動在任何沒有 return 敘述的函數結尾補上 return None；就算你寫了 return 但沒接任何值，也一樣回傳 None。

⚠ 常見誤區：忘了 return，只用了 print

下面這個函式想把加總結果「傳回去」給呼叫者使用，卻誤用了 print：
def add_em(x, y, z): print(x + y + z)
執行時看起來「有印出結果」，很容易誤以為函式運作正常——但它的傳回值其實是 None！如果之後寫 total = add_em(2, 3, 4)，total 拿到的會是 None 而不是 9。要讓函式真正「傳回」一個值，必須用 return，而不是 print。

另外要特別注意：return 敘述會立即結束函數，執行權馬上回到呼叫處，寫在 return 之後的程式碼永遠不會被執行到：

def add_em(x, y, z): return x + y + z print("the answer is", x + y + z) # ← 這行永遠不會執行！

PART 05 · 區域變數與全域變數

範圍（Scope）：變數活多久、誰看得到

函式被呼叫時建立的參數，以及在函式內被賦值的變數，都住在這個函式自己的區域範圍（local scope）。在所有函式之外被賦值的變數，則住在全域範圍（global scope）。一個變數只能屬於其中一種範圍，不能又是區域變數、又是全域變數。

換個白話的說法：函式就像一間房間，裡面的變數是寫在房間自己的白板上；房間門一關（函式執行結束、回傳），白板就被擦掉——房間外的人看不到、也拿不到裡面白板上的內容。

把「範圍」想像成變數的容器：範圍被銷毀時，裡面所有的變數也會被遺忘。一個模組只有一個全域範圍，程式開始執行時就建立；而每呼叫一次函式，就會產生一個新的區域範圍，函式執行完畢回傳後，該區域範圍就被銷毀。也就是說，下次再呼叫同一個函式，區域變數並不會記得上一次呼叫時的值。

情境一：區域變數無法在全域範圍中使用

def spam(): eggs = 31337 spam() print(eggs)
Traceback (most recent call last): NameError: name 'eggs' is not defined

變數 eggs 只存在於呼叫 spam() 時建立的區域範圍中；函式回傳後，該區域範圍就被銷毀，eggs 也不再存在。

情境二：不同的區域範圍互不相通

def spam(): eggs = 99 bacon() print(eggs) def bacon(): ham = 101 eggs = 0 spam()

bacon() 裡的 eggs，跟 spam() 裡的 eggs 是完全不同的兩個變數——它們分別存在於各自呼叫所建立的區域範圍中。bacon() 執行完畢回傳後，它的區域範圍（含 ham 與那個 eggs）就被銷毀；回到 spam() 後印出的 eggs，仍然是 spam() 自己的 99。

情境三：全域變數可以在區域範圍中被讀取

def spam(): print(eggs) eggs = 42 spam() print(eggs) # 輸出：42 # 42

因為 spam() 裡沒有名為 eggs 的參數，也沒有任何指派給 eggs 的敘述，所以 Python 會把它當成全域變數 eggs 來讀取——這正是「讀取全域變數」與下面「情境四：指派會建立區域變數」之間關鍵的不同之處。

🎬 情境四（互動）：函數內指派 → 建立區域變數，不影響全域同名變數

只要在函式內對某個名稱做指派（=），Python 就會把它視為區域變數——就算全域範圍已經有同名變數也一樣！這種現象叫做遮蔽（shadowing）。逐步執行下面的程式，觀察「全域」與「區域」兩欄裡的 eggs 如何互不干擾：

def spam(): eggs = 'spam local' print(eggs) # 'spam local' def bacon(): eggs = 'bacon local' print(eggs) # 'bacon local' spam() print(eggs) # 仍是 'bacon local' eggs = 'global' bacon() print(eggs) # 'global'

如果真的想修改全域變數：global 關鍵字

def spam(): global eggs # 如果想修改全域變數 eggs，必須使用 global 關鍵字 eggs = 'spam local' print(eggs) # 輸出 'spam local' eggs = 'global' spam() print(eggs) # 輸出 'spam local'

加上 global eggs 後，函式內的 eggs = 'spam local' 就不再建立區域變數，而是直接修改全域變數本身，所以最後 print(eggs) 印出的是 'spam local'。

⚠ 常見誤區：讀全域可以，但「指派」會變成區域變數

在函式內單純讀取一個名稱（例如 print(eggs)）沒有問題，Python 會沿用全域變數；但只要函式內有任何一行對這個名稱做了指派（例如 eggs = eggs + 1），Python 在編譯這個函式時就會把它整個視為區域變數——即使指派發生在讀取之後，也會導致「在指派前就使用了區域變數」的 UnboundLocalError！這是初學者非常容易踩到的陷阱（下方測驗會考到這一題）。

👨‍⚕️ 除非有非常充分的理由，否則不要用全域變數

全域變數的問題在於，它們很容易在整個程式中造成無意間的改動：在某個函式裡修改全域變數也許合理，卻可能干擾到其他所有函式的執行流程。函式的價值正在於它們的區域範圍——一個函式內的程式碼不會直接影響其他函式的變數，這讓除錯變得容易許多。

PART 06 · 把函式存進模組

模組（Module）：把函式存成獨立檔案並重複使用

把函式儲存在一個獨立的 .py 檔案中，這個檔案就稱為模組，之後可以用 import 陳述式把模組中的程式碼載入到目前的程式裡。這樣做能隱藏實作細節、讓你專注於高層邏輯，也方便在不同程式間重複使用同一批函式，甚至分享給其他程式設計師。假設我們建立了一個 pizza.py：

# pizza.py def make_pizza(size, toppings): """概述我們即將製作的披薩。""" print("\n正在製作一個 " + str(size) + " 吋的披薩，配料有：") print(toppings)
匯入語法呼叫方式範例備註
import 模組名模組名.函式()import pizza
pizza.make_pizza(16, '義式臘腸')		最安全，不會有名稱衝突
from 模組 import 函式函式()from pizza import make_pizza
make_pizza(16, '義式臘腸')		呼叫時不需要點記號
from 模組 import *函式()from pizza import *
make_pizza(16, '義式臘腸')		大型模組不建議，可能覆蓋同名函式
from 模組 import 函式 as 別名別名()from pizza import make_pizza as mp
mp(16, '義式臘腸')		函式名稱太長或會衝突時使用
